# 설계: 우리 아이 영양제 신뢰 체커 (올웨이즈 과제)

> 작성일 2026-05-29. 문제 정의 답변 + MVP 아키텍처를 함께 담는다.
> 근거 통계 출처는 `docs/personas/99-sources.md` 및 본 문서 말미 리서치 로그 참조.

## 0. 한 줄 정의
엄마가 **아이 나이 + 지금 먹이는 제품 + 새 후보**를 넣으면, AI가 **성분 중복·과다·연령 적정성을 근거·출처와 함께** 검증해 주는 신뢰 에이전트. *계산은 코드, 설명은 LLM, 근거는 RAG.*

## 1. 문제 정의 답변 구조 (과제 4문항 = 깔때기)

채용 과제의 평가 대상은 "정답"이 아니라 **"문제에 도달한 과정"**. 따라서 답변은 결론이 아니라 발산→수렴 깔때기로 제시한다.

```
[1] 발산: 35-50 여성 쇼핑 페인 후보 (카테고리 레벨)
[2] 스코어링: 5+1축으로 후보 재평가  → 영양제 선택
[3] 수렴: 페르소나 P3 + "왜 가장 아픈가"(3중 페인)
[4] 해결: MVP + 차별점 + 가설/실험 + 확장 비전
```
매핑: [2]→Q1(카테고리) · [1]+근거→Q2(문제) · [3]→Q3(페르소나) · [4]→Q4(MVP)

### 1.1 카테고리 발산 스코어링 (Q1 "과정"의 핵심 — 신규 보강)

실제 리서치(2026-05-29, 병렬 조사)로 3개 후보를 동일 축으로 재평가. 자체점수가 아닌 **비판적 재정규화 + 신규성 축 추가** 결과:

| 축 | 영양제 | 유아·생활용품 | 신선·가공식품 |
|---|:--:|:--:|:--:|
| 페인 강도 | 5 | 4.5 | 5 |
| 페르소나 선명도 | 5 | 4 | 5 |
| AI Agent 적합성 | **5** | 4 | **3.5** |
| 올웨이즈 정렬 | 3.5 | 4 | **5** |
| MVP 2일 실현성 | 4 | 4 | 4 |
| 차별성/신규성 ★ | **5** | 2.5 | 3.5 |

**선택 = 영양제.** 결정 근거 3가지:
1. **헤드라인 페인 × AI 적합성 일치** — 식품의 최강 페인(원산지 진위)은 LLM이 물리 검증 불가 → 2순위 페인으로 후퇴해야 함. 영양제는 *가장 아픈 페인(중복·과다 계산)이 곧 AI가 가장 잘 푸는 문제*.
2. **선점 여부** — 유아용품 성분등급은 맘가이드가 이미 점유. 영양제의 특정 job("지금 먹이는 것들과의 중복·과다를 연령 기준으로")은 빈 칸.
3. **올웨이즈 정렬 약점은 확장 비전으로 상쇄** — 영양제를 *웨지*로, 식품·유아용품을 *확장 로드맵*으로(동일 패턴 = "성분 신뢰 에이전트"). + 번들 전략(§7)으로 정면 보강.

### 1.2 수렴 페르소나 (Q3)
"박은정" 44세, 초등 자녀 2명, 맞벌이. 종합비타민·유산균·비타민D 급여 중, 환절기 면역 영양제 추가 검토. **3중 페인**: 안전(실패=죄책감) · 반복성(환절기마다 재발, 월 11.1만원) · 미해결(기존 도구가 연령 기준 중복점검 안 함).

## 2. MVP 아키텍처 (A안: 룰 계산 + 얇은 RAG grounding)

```
[쇼핑 중 장바구니에 어린이 영양제 담음]  ← 진입점(커머스 내장)
        │  트리거: cart에 ageTarget=kids 상품 ≥1
        ▼
[나이만 입력] ─▶ ① 단독 안전 체크 즉시 표시       ← 1단계(필수, 마찰 최소)
        │
        ▼ (선택)
["다른 영양제도 먹나요?" → seed에서 추가]          ← 2단계(차별화 = 중복체크)
        │
        ▼
① 성분 구조화        (seed JSON → DB)
② 단위 정규화        (코드 룰: mg/IU/mcg/㎍)
③ 합산·UL비교 판정   (코드 룰)        ◀ 계산은 코드
        │
        ▼
④ RAG: 기준문서 검색 (Supabase pgvector)  └ 성분×연령별 top-k 근거
        │
        ▼
⑤ LLM 설명 생성 + 출처 인용           ◀ 설명만 LLM
⑥ 대안/검증된 세트 추천 (seed 룰 필터)
        │
        ▼
[신뢰 리포트 카드/표 + 면책]
```

### 2.0 온보딩 흐름 (진입점 = 장바구니 트리거, 점진적 공개)
- **진입점**: 독립 폼이 아니라 **쇼핑 흐름에 내장**. 장바구니에 `ageTarget=kids` 상품이 1개 이상 담기면 체커 트리거. → "쇼핑 중 구매 결정을 돕는 에이전트" = 올웨이즈 정렬↑.
- **점진적 공개로 마찰↔가치 동시 해결**:
  - **1단계(필수, 5초)**: 나이만 → *그 제품 단독*으로도 과다 판정 가능. 근거: 약사회 실측 단일 구미가 권장량 500% → 기존 복용 0개여도 즉시 가치 전달.
  - **2단계(선택, 차별화)**: "다른 것도 먹고 있다면 추가" → 중복·합산 체크. 진짜 차별점이지만 마찰이라 선택적.
- **다자녀**: MVP는 1회 검사 = 아이 1명(나이 1개)로 단순화.

### 2.1 컴포넌트 매핑
| 레이어 | 역할 |
|---|---|
| web (Next.js) | 장바구니 UI(seed 선택) · 나이 입력 · "검사" 버튼 · 리포트 카드/표 · 추천 세트 카드 |
| api (NestJS) | `POST /analyze` 오케스트레이션. 모듈: ingredients → assessment(룰) → grounding(RAG) → explain(LLM) → recommend |
| Supabase + Prisma | `Product`(seed, 일반 테이블) + `Standard`(연령별 기준, **pgvector**) |
| OpenAI API | 임베딩 + 설명 생성. 키는 **백엔드에만** |
| seed 스크립트 | iHerb 크롤링→products seed · KDRIs PDF 정규화→standards→embed→DB |

### 2.2 RAG 레이어
- **코퍼스**: KDRIs 2020 연령별 권장량·상한(UL). **핵심 5~8개 성분**: 비타민 D·A·E·C, 칼슘·철·아연·유산균.
- **청킹**: `성분 × 연령대` = 1 chunk = 1 근거.
- **검색**: 판정된 성분마다 `"{성분} {나이}세 권장량 상한"`으로 top-k(1~3) retrieve.
- **RAG의 진짜 값**: 성분명 표기 흔들림 흡수(비타민D=콜레칼시페롤) + LLM이 실제 원문 인용 → 환각 차단.

### 2.3 데이터 소스 (크롤링 검증 결과 2026-05-29)
| 용도 | 소스 | 비고 |
|---|---|---|
| **SKU 성분·함량** | **iHerb 키즈 영양제 20~30개** | Supplement Facts가 **HTML 텍스트 표**(이미지❌) → 파싱 정확. robots /pr/ 허용, 안티봇 존재 → 정상 헤더·저빈도·1회 수집 후 JSON 캐싱. 히어로 사례(비타민D 구미 500%)도 커버 |
| **연령별 UL/권장량** | **KDRIs 2020 PDF** (복지부·영양학회) | 연령 구간별 권장량·상한 공식 기준 → 수기 정규화해 standards 테이블. 공공누리 *비상업* 라이선스(과제 데모 무방, 실서비스 시 확인) |
| 원료 상·하한 / 제품 승인 | 식약처 식품안전나라 API | 보조·교차검증용. **개별 SKU 함량(배합비)은 비공개**, 일반식품 구미 미커버 → 1차 소스 아님 |
| ❌ 제외 | 쿠팡·네이버 | 함량이 상세 **이미지(JPG)** + 강력 안티봇(Akamai/캡챠). 2일 내 부적합 |

> **입력 방식은 "seed 선택만" 유지** — 바뀐 건 *seed를 채우는 방법*(수기 → iHerb 크롤+수기 정규화)일 뿐. 사용자는 여전히 카탈로그에서 선택. 카탈로그에 없는 기존 복용 제품은 정직하게 `UNKNOWN "확인 불가"`.

### 2.4 `/analyze` 계약
```jsonc
// 요청
{ "child": { "ageYears": 8 },
  "products": [ {"id":"seed-123"}, {"id":"seed-456"} ] }   // MVP: seed 선택만

// 응답 (성분별)
{ "byNutrient": [{
    "nutrient":"비타민D", "total":25, "unit":"㎍",
    "sources":[{"product":"A","amount":10},{"product":"B","amount":15}],
    "standard":{"rda":5,"ul":25,"ageBand":"6-8","sourceUrl":"...","citedText":"..."},
    "verdict":"OVERDOSE",        // OK | OVERLAP(중복이나 UL이하=안전) | OVERDOSE | UNKNOWN
    "explanation":"..."          // LLM, grounded only
  }],
  "alternatives":[...],
  "disclaimer":"본 결과는 참고용이며 약사·소아과 상담 권장" }
```

## 3. 빌드 순서 (수직 슬라이스 — 룰 코어 먼저)
> 안전 제품이라 **계산 정확성이 최우선**. AI/RAG는 신뢰 래퍼이지 가치의 핵심이 아니다.
1. **데이터**: KDRIs 기준 코퍼스(성분 5~8개) 수기 정리 + iHerb products seed 20~30개
2. **룰 계산 코어** (AI 0%): 구조화 입력 → 합산 → UL 비교 → 판정. 순수함수 + 단위 테스트
3. **`/analyze` 골격** (설명 mock)
4. **RAG grounding** 부착: standards 임베딩 → pgvector → retrieve → LLM 설명
5. **프론트** 장바구니 트리거 + 점진적 공개 + 리포트 카드
6. **대안/검증된 세트 추천** (seed 룰 필터)
7. **배포**: web→Vercel, api→Railway, DB→Supabase

## 4. 신뢰/에러 설계 + 엣지케이스 (점수 갈리는 곳)

**판정/신뢰**
- **거짓경보 금지** — 중복이지만 UL 이하면 `OVERLAP`을 *"안전 범위"*로 명확히 구분. 79% 불신 고객층에 늑대소년이 되면 끝.
- 코퍼스(5~8개) 밖 성분 = `UNKNOWN "확인 불가"`, LLM 추측 금지.
- LLM 프롬프트: **"제공된 수치/근거만 사용, 없으면 확인 불가"** → 환각 차단.
- 단위 환산 실패(IU 모호 등) → 조용히 계산하지 말고 flag.
- 지용성(A·D·E) 축적 vs 수용성 → 경고 톤 차등. 면책 항상 첨부.

**엣지케이스 (🔴 MVP 필수 / ⚠️ 주의 / ✂️ 제외)**
- 🔴 트리거 감지: seed `category/ageTarget` 태그로 어린이 대상만. 비대상이면 트리거 안 함.
- ✂️ 성인+아이 혼합 장바구니 → 아이 대상만 필터.
- ⚠️ "가족용/전연령" 모호 제품 → 어린이 대상 간주 + 면책 강화.
- 🔴 다자녀 → MVP는 1회=1아이.
- ⚠️ 만 1세 미만 → 기준 상이, "범위 밖·전문가 상담"으로 제외.
- 🔴 나이 스킵 → 판정 불가, "확인 불가 + 일반 정보"로 degrade.
- 🔴 기존 복용 제품이 카탈로그에 없음 → `UNKNOWN`(seed-only 유지).
- ⚠️ 종합비타민(성분 多) → 중복 표면 넓음, 합산 로직 핵심 테스트 케이스.

## 5. 스코프 컷 (YAGNI)
- **포함**: 장바구니 트리거 · 나이 입력 · seed 상품 선택 · 중복·과다 리포트(근거) · 대안/검증된 세트 카드 · 배포 데모
- **제외**: 회원가입·로그인·사용자 DB, **결제·실제 세트 판매**, 자유입력 상품(LLM 추출), 다카테고리, 실시간 크롤링, 효능 판단, 영양제 자체 제조(PB)

## 6. 가설 / 실험
- H1(문제): 타깃 엄마는 복용 제품 간 중복·과다를 모르며 강한 불안.
- H2(불신): 기존 리뷰·커뮤니티 정보를 신뢰 안 함.
- H3(솔루션): 근거·출처 붙은 점검 결과 → 신뢰 생기고 구매 결정 바뀜.
- 지표: 입력 완료율 · 결과 신뢰도(5점) · 대안/세트 수용률 · 재사용 의향.
- 판단: 완료율 60%+ & 신뢰도 4점+ → H3 지지.

## 7. 번들/세트 전략 (확장·수익화 비전 — MVP 데모 밖)

> 핵심 솔루션은 "신뢰 체커"(진단). 번들은 진단 다음의 *답*을 주어 커머스로 닫는 **확장·수익화 레이어**.

**핵심 긴장**: 검증자가 판매자가 되면 79% 불신 고객이 의심하는 "이해관계 있는 추천자"가 됨 → 신뢰 명제 훼손 위험.

**선택 모델 = 검증된 조합(투명)**: 자체 PB 제조(❌, 신뢰 리스크 + MVP 밖)가 아니라, **기존 제품을 묶되 세트마다 "연령 기준 중복0·과다0 + 근거" 검증 리포트를 그대로 첨부.** 신뢰는 결과를 숨기지 않는 데서 온다(§4 3원칙과 일치).

**왜 강력한가**
1. 올웨이즈 정렬(약점 축)을 정면 보강 — 정보 도구 → 커머스 플라이휠.
2. 올웨이즈 **공동구매 모델**과 정확히 맞음("8세용 검증 면역 세트"를 공동구매).
3. 3중 페인의 *반복성*을 수익화 — "환절기 면역 세트, 검증완료" = 구독/재구매 = 북극성·리텐션.

**위치**: 과제 답변에선 수익화/올웨이즈 정렬/북극성 비전. MVP 데모에선 체커 결과의 **"이 조합 대신 ✅검증된 세트" 추천 카드까지만**(구매는 mock/링크). P3 날카로움 유지 위해 핵심은 체커, 번들은 확장.

## 8. 확정된 결정 로그 (2026-05-29 브레인스토밍)
- 문제 카테고리: **영양제** (3후보 발산→재정규화 후 선택) + 식품·유아용품 확장 비전
- 파이프라인: **A안** (룰 계산 코어 + 얇은 RAG grounding)
- RAG 코퍼스: **핵심 5~8개 성분**, KDRIs 2020 기준
- 빌드 순서: **룰 계산 코어 먼저**
- 입력 방식: **seed 선택만** (자유입력 제외) — seed는 iHerb 크롤+수기 정규화로 채움
- 온보딩: **장바구니 트리거 + 점진적 공개**(나이→단독결과→선택적 중복체크), 1회=1아이
- 데이터 소스: **iHerb(함량) + KDRIs(기준) + 식약처API(보조)**, 쿠팡·네이버 제외
- 거짓경보 금지: `OVERLAP`(UL이하)는 "안전 범위"로 구분
- 번들: **검증된 조합(투명)** 모델, **확장·수익화 비전**(MVP 데모는 추천 세트 카드만)
- 저장소: Supabase Postgres + pgvector(기준문서), Prisma
