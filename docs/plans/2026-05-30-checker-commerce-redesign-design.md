# 설계: 영양제 안전 체커 — 커머스형 화면 재구성

> 작성일 2026-05-30. 기존 단일 스크롤 체커를 **실제 커머스(vitaminshop.co.kr 상품 진열) 형태의
> 단계 흐름**으로 재구성한다. 레퍼런스: https://vitaminshop.co.kr/ — **상품 진열 구조만** 참고.

## 0. 한 줄 정의

페르소나 선택 → (커머스형) 제품 담기 → 나이 입력 → 안전 리포트로 이어지는 **4단계 스텝 흐름**.
제품 담기 단계를 실제 쇼핑몰 상품 그리드(이미지·정상가·판매가·할인율·장바구니)처럼 보이게 한다.
**안전 판정 룰 엔진은 일절 변경하지 않는다 — 가격·이미지는 표시 전용.**

## 1. 배경 / 문제

현재 `/check`(및 임시로 `/`)는 페르소나 랜딩 이후 **제품 담기·나이·결과가 한 페이지에
스택되어 스크롤**로 진행된다. 단계 인지가 약하고, "영양제를 담는다"는 행위가 커머스답지 않다.
사용자 요구: **(1) 유저 시퀀스(상황→제품→나이→결과)에 맞게 단계화, (2) 실제 커머스처럼
상품을 이미지·가격과 함께 진열.**

## 2. 결정 사항 (브레인스토밍 합의)

| # | 항목 | 결정 |
|---|------|------|
| D1 | 흐름 구조 | **단계별 위저드(스텝퍼)** + 하단 **스티키 카트바** |
| D2 | 상품 진열 | vitaminshop **상품 카드 구조** 모사 (이미지+정상가 취소선+판매가+할인율%+칩) |
| D3 | 이미지 | vitaminshop 상품 이미지 ~24장을 **로컬 다운로드**(`public/products/`) 후 랜덤 매핑 (런타임 핫링크 X) |
| D4 | 가격 | DB에 **랜덤 정상가/판매가/할인율** 백필해 표시 (데모 더미) |
| D5 | 세트상품 | **기존 페르소나 프리셋을 "테마 세트" 카드로 재활용** (새 DB 엔티티 없음) |
| D6 | 라우팅 | **체커 = 홈 `/`**, `/check`는 `/`로 **리다이렉트** (현재 이중 마운트 정리) |
| D7 | 룰 엔진/분석 | **변경 없음** — 가격·이미지는 판정과 무관, 표시 전용 |

> ⚠️ **정직성/라이선스**: 타사(vitaminshop) 이미지와 더미 가격은 **POC 데모 한정**.
> 코드 주석·시드 스크립트·문서에 더미임을 명시한다. 이 앱의 "신뢰 체커" 메시지와 충돌하지
> 않도록, 안전 판정 결과에는 가격/이미지를 근거로 쓰지 않는다.

## 3. 사용자 흐름 (스텝퍼)

```
상단 진행 표시:  ●──●──○──○   (1.상황  2.제품  3.나이  4.결과)

[1] 상황 고르기   페르소나 카드 4종 (= 테마 세트 진입점)
       │  선택 시 나이·장바구니 프리필
[2] 제품 담기     커머스형 4열(모바일 2열) 상품 그리드
       │  카드 = 이미지 + 정상가(취소선) + 판매가 + 할인율% + [담기]
[3] 나이 입력     만 나이 한 줄 입력 (페르소나면 프리필)
[4] 안전 리포트   성분별 판정(SAFE/DUPLICATE/OVER/UNKNOWN) + 검증된 세트

하단 스티키 카트바 (모든 단계 공통):
[ 🛒 담은 제품 N개  ·  성분 미리보기 ]            [ 다음 → ]
```

- 단계 전환은 화면 교체(스텝퍼). "← 뒤로 / 다음 →" 또는 진행 표시 클릭.
- 스티키 카트바: 담은 개수 + 다음 단계 CTA를 항상 노출(모바일 커머스 패턴).
- 상태는 단일 클라이언트 컴포넌트에서 관리(현 `page.tsx` 패턴 유지), `step` 상태 추가.

## 4. 상품 카드 사양 (Image #1 구조)

```
┌───────────────────────┐
│  [new]      ┌────────┐ │   · 파스텔 라운드 배경 + 상품 이미지(next/image)
│   파스텔     │ 이미지  │ │   · (옵션) 좌상단 new 뱃지
│   배경      └────────┘ │   · 우하단 [담기] 아이콘 버튼 (Heroicons SVG, 이모지 X)
│                    🛒  │
├───────────────────────┤
│ 닥터엘리자베스 …(2줄)    │   · 상품명 최대 2줄 (line-clamp-2)
│ 정상가: 45,000          │   · 정상가 취소선(회색)
│ 판매가: 27,000  40%     │   · 판매가 굵게 + 할인율%(빨강)
│ [구미] [만8세] [비타민D] │   · 제형/연령/주요성분 칩
└───────────────────────┘
```

- 선택(담김) 상태: 테두리·링 강조(현 ProductPicker의 `aria-pressed` 유지) + [담기]→[✓ 담음].
- 접근성: 가격은 색 단독 신호 금지(텍스트 라벨 동반), 카드 버튼 `aria-pressed`, 이미지 `alt`.

## 5. 데이터: 스키마·백필·API

### 5.1 스키마 (`apps/api/prisma/schema.prisma`)
- `Product`에 `listPrice Int?` 추가 (= 정상가). 기존 `price Int?`는 **판매가**로 사용.
- 할인율 % = `round((listPrice - price) / listPrice * 100)` — 저장하지 않고 계산.
- `imageUrl String?` (이미 존재) 사용.
- `db push`로 반영(마이그레이션 파일 불필요한 환경 — DIRECT_URL).

### 5.2 백필 스크립트 (1회 실행, `apps/api/prisma/`)
1. vitaminshop에서 상품 이미지 ~24장 다운로드 → `apps/web/public/products/p01.jpg …`
   - 본 세션에서 추출 확인된 패턴: `https://vitaminshop.co.kr/web/product/medium/*.jpg`
2. 30개 `Product`에 랜덤으로: `imageUrl`(로컬 경로 `/products/pNN.jpg`), `listPrice`(정상가),
   `price`(판매가 = 정상가 × (1 - 랜덤할인 0.2~0.5)) 매핑.
3. **결정성**: 랜덤은 시드 고정(제품 id 기반 의사난수)으로 재실행 시 동일 결과 — 데모 안정성.
4. 스크립트/주석에 "데모 더미 데이터" 명시.

### 5.3 API (`apps/api/src/products/`)
- `ProductsService.list()`의 `CatalogProduct` 매핑에 `imageUrl`, `price`, `listPrice` 추가.
- 웹 `apps/web/src/libs/Api.ts`의 `CatalogProduct` 타입에 동일 필드 추가(`number | null`, `string | null`).
- `/analyze` 및 룰 엔진 입력/출력은 **무변경**.

  예) `면역 케어맘` → "5~8세 면역 케어 세트", `초보맘` → "유아 첫 영양제 세트".

## 8. 비주얼 시스템

- ui-ux-pro-max(헬스케어-클린) 방향: flat, 여백 충분, 신뢰 지향.
- 기본 컬러는 현 블루(#blue-600) 계열 유지(브랜드 일관성), 가격 할인율만 빨강 강조.
- **이모지 → SVG 아이콘**: 장바구니/체크/정보 등은 Heroicons로 교체. (페르소나 이모지는
  장식용으로 유지 가능 — `aria-hidden`.)
- 트랜지션 150–300ms, `cursor-pointer`, 포커스 링, `prefers-reduced-motion` 준수.
- 반응형 검증: 375 / 768 / 1024 / 1440.
