# "우리 아이 영양제 신뢰 체커" — MVP 고려사항 브레인스토밍

> 목적: 과제1의 MVP를 과제2(React + Node.js + ChatGPT API + 크롤링 + 배포)로 **2일 안에** 구현하기 위해 미리 짚어야 할 점들.
> 원칙: 화려함 < 본질. "근거 기반(환각 방지) + 개인화(아이 맥락) + 신뢰"를 시연하는 가장 얇은 칼.

---

## 0. 이 MVP가 '증명'하려는 것 (한 문장)
> "엄마가 지금 먹이는 제품 + 새 후보를 넣으면, **아이 연령 기준으로 성분 중복·과다 여부를 근거와 출처와 함께** 검증해 준다."

레브잇 명제와 정렬: ① 행동기반이 아닌 **근거기반 추천**, ② 환각 방지를 위한 **실데이터 grounding**, ③ "한 번 잘못된 정보 = 이탈"에 대응하는 **신뢰 우선 설계**.

---

## 1. 신뢰·안전 설계 — 가장 중요한 차별점 (여기서 점수가 갈린다)

- **계산은 코드, 말은 LLM** — 중복·과다 "합산/판정"을 LLM에 맡기면 틀린다. **합산·상한 비교는 결정론적 코드(룰)**로, LLM은 **(a) 라벨 텍스트 → 구조화 성분 추출**, **(b) 결과를 쉽게 설명**하는 역할만.
- **환각 방지(grounding)** — ChatGPT가 함량을 지어내지 않도록, 모든 수치는 **크롤링한 실제 라벨 데이터**에서만. 출력에 "이 수치의 출처(제품/링크)"를 항상 표기.
- **모르면 모른다고** — 데이터 없는 성분은 "확인 불가"로 명시. 79.2%가 정보를 의심하는 고객층엔 **정직이 곧 신뢰**. ([근거: 엠브레인 트렌드모니터](../personas/99-sources.md))
- **연령 기준의 출처** — 상한섭취량(UL)·권장량은 KDRIs/식약처 같은 **공개 기준을 인용**해 판정 근거로. (예: 비타민D 소아 600IU, 상한 4,000IU)
- **의학 면책** — "본 결과는 참고용이며 약사·소아과 상담을 권장합니다." 과신을 막아 오히려 신뢰를 높인다.

## 2. 데이터·크롤링 (제약 충족 + 현실적 범위)

- **무엇을 크롤링** — 영양제 상품의 *제품명·대상연령·성분·함량(단위)·가격*. 과제는 "최소한의 크롤링 연동"을 보는 것이라 **다양성·퀄리티 불필요**(명시됨).
- **소스 선택 주의** — 쿠팡·네이버는 크롤링 차단·약관 이슈가 큼. **브랜드몰/아이허브/공개 상세페이지** 등 가벼운 대상으로, 소수(10~30개)만.
- **사전 크롤링 → JSON 캐시** — 런타임 실시간 크롤링은 느리고 데모가 깨진다. **빌드 전 스크립트로 한 번 긁어 `products.json`** 으로 고정 → 데모 안정성 확보.
- **단위 정규화** — mg/IU/mcg/㎍ 혼재 + IU는 성분별 환산식이 다름. **정규화 매핑 테이블**을 코드로(LLM 추출 후 룰로 변환).

## 3. 스코프 컷 — 2일 안에 끝내는 법 (제일 현실적인 조언)

**반드시(MUST)**
1. 아이 정보 입력(나이) 2. 현재 먹는 제품 + 새 후보 선택/입력 3. **중복·과다 점검 결과(근거 포함)** 4. 크롤링 데이터 기반 **대안 1~2개 추천(이유 명시)** 5. **배포 + 외부 링크**

**버린다(CUT)** — 회원가입·로그인·DB, 결제, 다(多)카테고리, 실시간 크롤링, 모바일 완벽 대응, 정교한 디자인, 사용자 데이터 저장.

> 평가 포인트는 "문제 해석·해결 과정"이지 기능 수가 아니다. **얇고 정확한 한 흐름**이 넓고 엉성한 다섯 기능을 이긴다.

## 4. UX / 대화 흐름

- 과제가 **"대화형 AI"**를 요구 → 챗 입력은 두되, **출력은 표/카드(구조화)** 로. 순수 챗봇보다 "챗 입력 → 신뢰 리포트" **하이브리드**가 신뢰감↑.
- 결과 카드 예: `비타민D — 제품A 10㎍ + 제품B 15㎍ = 25㎍ (8세 권장 5㎍의 500%) ⚠️ 과다`. + 출처 링크 + 한 줄 설명.
- P2(시간빈곤) 반영: **5분 내 결론**. 입력 마찰 최소화(시드 제품은 선택형 + 자유입력 보조).

## 5. 기술 아키텍처 (과제2 제약 내, 가장 단순한 형태)

- **Front (React)**: 단일 화면 — 입력 폼/챗 + 결과 리포트.
- **Back (Node.js/Express)**: `POST /analyze` — 입력 받아 ① LLM 성분 추출 ② 룰 기반 중복·과다 계산 ③ LLM 설명 생성 → JSON 반환. **ChatGPT API 키는 백엔드에만**(프론트 노출 = 보안 사고).
- **크롤링**: 별도 스크립트(cheerio/puppeteer) → `products.json` 시드.
- **배포**: 프론트 Vercel + 백 Render/Railway, 또는 한 곳으로 묶기. **가장 빠른 경로 우선**(데모 링크가 목적).

## 6. 평가 정렬 / README (놓치면 아까운 점수)

- 과제 평가 = **문제 해석 + 해결 과정**. README 하단에 **"막힌 점 → 해결" 로그** 필수:

## 결정이 필요한 열린 질문 (당신이 정할 것)
1. **입력 방식**: 자유 텍스트(LLM 파싱, 유연하지만 불안정) vs 선택형(안정적, 데모 깔끔) vs 하이브리드?

4. **대화 톤**: 순수 챗봇 vs 폼 입력 + 구조화 리포트(추천)?
